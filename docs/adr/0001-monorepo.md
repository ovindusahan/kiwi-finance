# 0001. One repository for backend, web, iOS and contracts

| Status | Date |
| --- | --- |
| Accepted | 2026-10-01 |

## Context

Kiwi Finance has a backend, a web app and, later, an iOS app. All three depend on the same
API contract. Spread across separate repositories, a contract change needs coordinated
pull requests in several places, and the clients drift out of step with the server.

## Decision

Keep everything in one repository with a top-level folder per deliverable:

| Folder | Contents | Tooling |
| --- | --- | --- |
| `backend/` | Spring Boot API and the finance engine | Gradle |
| `web/` | Next.js app | pnpm |
| `ios/` | SwiftUI app | Xcode |
| `contracts/` | Generated OpenAPI document | Generated by the backend build |
| `docs/` | Architecture, references, ADRs | Markdown and Mermaid |

Each folder keeps the native tooling of its ecosystem rather than forcing one build tool
over all of them.

## Consequences

- A contract change, its server implementation and its client usage can land in one pull
  request.
- CI runs each folder's checks only when that folder, or the contract, changes.
- Contributors need only the toolchain for the part they are working on.
